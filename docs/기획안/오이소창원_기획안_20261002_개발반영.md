### 3. 왜 ‘초기 180일’인가
들어온 청년이 자리 잡지 못하고 다시 떠나면 청년 유출은 멈추지 않습니다. 정착 지원 제도도 전입 초기를 기준으로 짜여 있습니다.

- 기업노동자 전입 지원금(창원시): 전입 후 6개월 이상 계속 거주해야 신청 가능
- 전입 대학(원)생 생활안정지원(창원시): 타 시·군·구 1년 이상 → 창원 전입, 관내 대학(원) 재학생, 월 6만원 최대 3년
- 청년일자리도약장려금(고용노동부): 비수도권 정규직 청년 근속 인센티브

> 180일 표기: 연구로 입증된 정착 기간이 아니라, 위 제도들의 기준(전입 후 6개월)을 참고해 팀이 정한 **서비스 설계 기간**입니다. AI가 인구 문제를 직접 해결한다고 주장하지 않고, 정착 과정의 정보 부담을 줄이는 데 초점을 둡니다.

### 5. 기존 서비스와 차별성
기존 서비스는 “무엇을 받을 수 있나”를 답하고, 오이소창원은 **“언제 무엇을 해야 하나”를 계획하고 기억**합니다.

| 기존 서비스 | 하는 일 | 오이소창원이 더하는 것 |
|---|---|---|
| 온통청년·청년몽땅정보통 | 청년 정책 검색·추천 | 창원 전입일 기준 신청 가능일 계산과 1~6개월 정착 일정 |
| 창원청년정보플랫폼 | 창원시 청년정책 검색·신청 | 생활정보(맛집·카페·야경·의료)·지역말까지, 개인 전입일 기준 일정. 신청은 플랫폼·공식 사이트로 연결(보완) |
| 창원 AI당직전문관 | 야간·휴일 민원 응대 | 불편의 긴급도 판단과 맞는 창구 안내 |
| 사투리 번역기 | 표준어↔사투리 변환 | 들은 말 이해 중심, 국립국어원 등 출처 표시, 모르는 말은 짐작하지 않음 |

## Ⅱ. 과제 목표 및 기대효과

### 1. 서비스 목표와 MVP 결과
대상은 창원에 새로 전입한 청년(19~39세)입니다.

| 서비스 | 목표 | MVP 결과(10/2) |
|---|---|---|
| ① 창원 청년 맞춤형 혜택 알림 | 해당 가능성이 있는 정책과 신청 시점을 안내 | 정책 **24건** 4단계 판정(해당 가능/조건부/직접 확인/해당 없음), 판단 이유·공식 링크·확인일 100% 표시, 180일 밖 날짜는 “(180일 이후)” 표시 |
| ② 창원 생활 정보 안내 및 일정 편성 | 정착 할 일 일정 + 관심사·생활권에 맞는 장소 | 정착 할 일 26개(1~6개월) 체크·메모·저장, 생활 정보 60곳(구·분야·실내 필터), 네이버 지도 검색 링크, 차량 권장 8곳 분리 안내 |
| ③ 불편사항 행정 접수안내 | 불편·위험을 알맞은 창구로 안내 | 6단계(긴급·높음·보통·제안·마음 건강·위기) 창구 안내, 긴급·위기 문장은 AI를 거치지 않고 즉시 112·119·109 |
| ④ 창원 지역말 번역 | 들은 지역말의 뜻을 안내 | 핵심 30개 + 공식 출처 확장 사전 **2,223개**, “문헌 기준 뜻”·출처 표시, 사전에 없는 말은 “별도 확인 필요” + 국립국어원 우리말샘 링크 |
| AI 코디에게 물어보기(Agent 입구) | 한 문장 질문을 이해하고 도구를 골라 답함 | GPT-4.1 mini가 도구 5개 중 선택·호출 → 답변 검증 → 실행 기록 표시, 실패 시 규칙 기반 안내로 자동 전환 |

실사용자 3명(또는 기관 담당자) 온라인 설문 만족도 평균 5점 중 4점 이상을 함께 목표로 합니다(10/3 진행).

### 2. 기대효과

- 사용자: 혜택 신청 시점을 놓치는 일과 여러 사이트를 검색하는 시간을 줄입니다.
- 창원시: 이미 있는 사업(전입지원금·청년월세 등)의 활용을 높여 새 예산 없이 정착을 돕습니다.
- 사회: 지방에 유입된 청년의 초기 정착을 도와 청년 유출과 인구소멸 위험에 대응합니다.
- 비즈니스 모델(B2G): 창원시·경남 시군에 전입자 정착 도구로 제공하고 전입신고 때 안내. 익명 집계 ‘전입자 정착 불편 리포트’는 시와 협의 후 도입.
- 확장: 청년 외 전입자(생애주기별 정책), 경남 타 시군으로 데이터만 바꿔 확산.

| 사이드바 | 정착 N일째 · 전체 진행률 · 메뉴(조건 입력·완료, 맞춤 혜택·해당 가능 N건, 정착 일정·이번 단계 s/t 등 실제 값만) |

- 대표 페르소나(시연용 가상값): 닉네임 **코디2026**(실명 받지 않음), 만 28세, 경기도 용인시 → 창원 전입(2026-09-20), 전입 전 타지역 2년, 창원 기업 직장인, 1인가구, 차량 없음(버스·자전거)
- 앱은 빈 칸으로 시작하고, ‘코디2026 예시로 둘러보기’를 누를 때만 페르소나 값을 채웁니다.

### 3. Agent 동작 흐름(실제 구현)
```
한 문장 질문
 → ① 안전 확인(긴급 112·119 / 위기 109는 AI 없이 즉시 안내)
 → ② 목표 인식: GPT-4.1 mini가 필요한 도구 선택
 → ③ 도구 호출: get_my_situation · search_policies · search_activities · lookup_dialect · find_complaint_channel
 → ④ 답변 검증: 답 속 전화번호·링크가 도구 결과(검증 DB)에 있는지 대조, 없으면 1회 다시 작성
 → ⑤ 결과: 답 + 관련 공식 링크 버튼 + Agent 실행 기록
 → (AI 연결 실패·검증 실패 시) 규칙 기반 안내로 자동 전환
```
대표 End-to-End: 나의 조건 입력 → ① 혜택 판정 → ② 정착 일정·할 일 체크 → 저장 → 새로고침 후 복원.

### 4. Agent 6요소
| 요소 | 오이소창원 적용 |
|---|---|
| 목표 인식 | 한 문장 질문에서 기능(①~④)과 긴급·마음 건강 신호 구분 |
| 계획 | 전입일 기준 1~6개월 할 일 순서, 신청 가능 예정일 계산 |
| 도구 호출 | 정책·지역활동·지역말·접수 창구 DB 조회, 사용자 상황 조회 |
| 판단 | 정책 4단계 판정, 긴급도 분류, 차량 여부에 따른 이동 방식 판단 |
| 결과 생성 | 맞춤 혜택 카드, 정착 일정, 추천 장소, 창구 안내, 뜻 풀이, 실행 기록 |
| 상태 저장(Memory) | 할 일 체크·메모를 닉네임 기준 SQLite 저장, 다시 열면 이어서 표시 |

### 5. 프롬프트·안전 원칙

- 답은 도구 결과(검증 DB)로만. 금액·기간·조건·연락처·링크는 DB 값 그대로, 추측 금지.
- 지원 대상 여부는 단정하지 않고 ‘해당 가능/조건부/직접 확인’으로 표현.
- 지역말은 사전에 있으면 ‘문헌 기준 뜻’, 없으면 짐작하지 않고 “별도 확인 필요” + 우리말샘 링크(콜센터 안내 안 함).
- 의학·법률 판단, 투자 등 범위 밖 질문은 정중히 거절하고 할 수 있는 일을 안내.
- 없는 URL·전화번호·정책·행사를 만들지 않음(검증 단계에서 차단).

### 2. 제약사항

- 개발 기간 8일 → 대표 흐름을 먼저 완성하고 범위를 줄임.
- 정책·활동 정보는 확인일 기준이며 바뀔 수 있음 → 모든 안내에 확인일·공식 링크.
- 자격을 확정하지 않고 “해당 가능성”으로만 안내, 신청·민원 제출은 사용자 본인이.

- 상업 시설은 “방문 전 운영시간 확인”, 특정 업체 홍보 아님.
- 배포 서버 재시작 시 저장 기록이 초기화될 수 있음(시연용 SQLite).
