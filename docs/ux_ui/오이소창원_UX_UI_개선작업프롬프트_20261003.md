# 오이소창원 UX/UI 개선 작업 프롬프트

## 목적

실사용자 테스트에서 다음과 같은 의견이 있었다.

-   앱의 전체적인 UI 완성도가 아쉽다.
-   첫 화면에서 무엇부터 해야 하는지 직관적으로 이해하기 어렵다.
-   개인 조건을 입력하기 전부터 사용할 수 없는 기능 버튼이 보이기 때문에
    사용 순서가 혼란스럽다.
-   기능은 충분하지만 한 화면에 정보가 많아 앱 사용이 어렵게 느껴질 수
    있다.

이번 작업의 목적은 **신규 기능을 추가하는 것이 아니라, 현재 검증된
기능과 데이터를 그대로 유지하면서 사용자가 다음 행동을 쉽게 이해할 수
있도록 전체 UX/UI를 개선하는 것**이다.

> 중요: 현재 기능과 데이터는 반복 테스트를 거쳐 정상 작동하고 있다. 정책
> 판정, Agent, 데이터, 저장 기능 등 기존 비즈니스 로직을 변경하지 말고
> UI/UX를 중심으로 최소 수정한다.

------------------------------------------------------------------------

## 1. 전체 UX 방향

오이소창원의 전체 디자인을 다음 방향으로 개선한다.

-   공공서비스의 신뢰감 유지
-   지나치게 딱딱한 행정 사이트 느낌은 줄이기
-   청년 대상 서비스에 맞는 깔끔하고 현대적인 화면
-   한 화면에 너무 많은 정보를 보여주지 않기
-   사용자가 현재 해야 할 행동을 바로 이해할 수 있게 하기
-   설명보다 핵심 행동 버튼이 먼저 보이도록 하기
-   PC와 모바일 모두 고려
-   과도한 색상, 테두리, 그림자, 이모지 사용 금지
-   글자와 카드, 카드와 카드, 섹션과 섹션 사이에 충분한 여백 확보

### 기존 브랜드 색상 유지

-   Navy: `#063465`
-   Orange: `#FE6A01`
-   Green: `#2E9E6B`

색상의 역할을 명확하게 구분한다.

-   **Navy**: 제목, 메뉴, 기본 강조
-   **Orange**: 사용자가 현재 가장 먼저 눌러야 하는 핵심 CTA
-   **Green**: 완료, 진행률, 검증 통과 상태

한 화면에서 Orange 핵심 버튼을 지나치게 많이 사용하지 않는다.

------------------------------------------------------------------------

## 2. 첫 방문 화면 단순화

사용자가 아직 개인 조건을 입력하지 않았다면 현재 전체 메인 홈을 바로
보여주지 않는다.

첫 화면의 핵심 목적은 하나로 한다.

**"내 조건을 입력하고 시작하기"**

권장 화면 구조:

1.  오이소창원 로고
2.  `창원에서 너의 내일을 응원해!`
3.  서비스 핵심 설명
4.  조건 입력 시작 CTA
5.  `코디2026 예시로 둘러보기`

서비스 설명 예시:

> 오이소창원은 창원에 새로 전입한 청년의 초기 정착을 돕는 코디네이터
> Agent입니다.\
> 창원에서의 첫 180일, 놓치기 쉬운 혜택과 할 일을 함께 챙겨드려요.

Primary CTA:

**\[조건 입력하고 시작하기\]**

조건 입력 전에는 맞춤 혜택, 정착 일정, 생활 정보, 불편사항, 지역말,
오이소창원에게 물어보기 등의 기능을 연한 비활성화 버튼으로 나열하지
않는다.

사용자가 지금 해야 하는 행동만 명확하게 보여준다.

------------------------------------------------------------------------

## 3. 조건 입력 화면 개선

현재 앱의 조건 입력 항목과 판정 로직은 그대로 유지한다.

폼이 길고 복잡해 보이지 않도록 입력 항목을 시각적으로 그룹화한다.

### 기본 정보

-   닉네임
-   나이

### 창원 정착 정보

-   전입일
-   거주 지역
-   동네(선택)
-   창원 전입 전 타지역 거주기간

### 생활 조건

-   지금 하는 일
-   차량 소지 여부

각 그룹 사이에 충분한 여백을 둔다.

입력창의 폭과 높이를 가능한 범위에서 통일하고 필수/선택 항목을 명확하게
구분한다.

하단 Primary CTA:

**\[조건 입력 완료\]**

보조 기능:

**\[코디2026 예시로 입력\]**

두 버튼의 시각적 중요도를 다르게 한다.

------------------------------------------------------------------------

## 4. 조건 입력 완료 후 화면 전환

`st.session_state` 등을 이용하여 현재 세션에서 조건 입력 완료 여부를
관리한다.

예:

`profile_completed = False / True`

조건 입력 전:

`첫 방문 안내 → 조건 입력`

조건 입력 완료 후:

`메인 정착 대시보드`

사용자가 `조건 확인·수정`을 선택하면 기존 조건을 불러와 수정할 수 있게
하고, 수정 완료 후 다시 메인 화면으로 돌아오게 한다.

회원가입을 하지 않는 현재 서비스 원칙은 변경하지 않는다.

세션이 초기화되거나 재접속할 경우 기존 내용이 사라질 수 있다는 현재 안내
원칙도 유지한다.

------------------------------------------------------------------------

## 5. 조건 입력 후 메인 홈 개선

기존 홈을 **정착 대시보드**처럼 재구성한다.

권장 상단 구조:

> 안녕하세요, 코디2026님\
> 창원 정착 14일째예요.

그 아래에 다음을 배치한다.

-   전체 정착 진행률
-   현재 단계
-   지금 하면 좋은 일 1\~3개

그 다음 핵심 기능을 보여준다.

사용자가 메인 화면에 들어왔을 때 모든 설명을 읽지 않아도 현재 상태와
다음 행동을 바로 이해할 수 있어야 한다.

------------------------------------------------------------------------

## 6. 핵심 기능 카드 개선

기존 4개 핵심 기능을 카드 형태로 정리한다.

PC: **2열 × 2행**

모바일: **1열**

### ① 창원 청년 맞춤형 혜택 알림

나에게 맞는 창원 청년 정책을 찾아드려요.

**\[혜택 확인하기\]**

### ② 창원 생활 정보 안내 및 일정 편성

정착 180일 동안 필요한 일을 챙겨드려요.

**\[정착 일정 보기\]**

### ③ 불편사항 행정 접수안내

생활 불편사항의 접수 창구를 찾아드려요.

**\[접수 안내 받기\]**

### ④ 창원 지역말 번역

낯선 지역말의 뜻을 확인해 보세요.

**\[지역말 확인하기\]**

카드마다 다음 요소를 통일한다.

-   제목 크기
-   설명 길이
-   카드 높이
-   버튼 위치
-   내부 여백
-   테두리
-   모서리 반경

카드 안에 긴 설명을 넣지 않는다.

------------------------------------------------------------------------

## 7. `오이소창원에게 물어보기` 영역 개선

`오이소창원에게 물어보기`는 4개 핵심 기능 중 하나가 아니라 **코디네이터
Agent의 통합 질문 진입 영역**이다.

따라서 4개 기능 카드와 별도로 구분한다.

권장 구조:

> ### 무엇을 도와드릴까요?
>
> **오이소창원에게 물어보기**
>
> 혜택, 정착 일정, 생활 정보, 불편사항, 지역말을 한 번에 물어보세요.

질문 입력창과 함께 예시 질문을 2\~3개 제공한다.

예: - 이번 주말 버스로 갈 만한 야경 명소 추천해 줘 - 내가 받을 수 있는
지원이 뭐야? - 정구지가 무슨 뜻이야?

4개 기능 카드와 시각적으로 구분하되 전체 브랜드 디자인은 유지한다.

------------------------------------------------------------------------

## 8. 정보 위계 개선

전체 화면을 점검하여 다음 문제를 개선한다.

-   제목과 본문의 크기 차이가 부족한 부분
-   글자가 너무 붙어 있는 부분
-   카드끼리 너무 붙어 있는 부분
-   버튼이 너무 많은 화면
-   설명 문장이 지나치게 긴 부분
-   같은 정보가 반복되는 부분
-   한 화면에 정보가 너무 많은 부분
-   중요하지 않은 정보가 핵심 행동보다 눈에 띄는 부분

정보 위계는 다음 순서를 기본으로 한다.

`페이지 제목 → 핵심 설명 → 현재 상태 → 주요 행동 → 상세 정보`

상세 설명은 필요할 경우 `expander` 또는 `자세히 보기` 안으로 이동한다.

------------------------------------------------------------------------

## 9. 여백과 레이아웃

전체 UI에서 여백을 적극적으로 사용한다.

다음 간격을 일정한 디자인 규칙으로 정리한다.

-   페이지 좌우 여백
-   제목과 본문 사이
-   본문과 버튼 사이
-   카드 내부 여백
-   카드와 카드 사이
-   섹션과 섹션 사이

요소들이 서로 붙어 보이지 않게 한다.

특히 모바일에서 카드와 버튼이 붙어 보이지 않도록 한다.

------------------------------------------------------------------------

## 10. 글자 스타일

글자 크기에 명확한 단계가 있도록 한다.

권장 기준:

-   메인 타이틀: 28\~32px
-   페이지 제목: 24\~28px
-   섹션 제목: 20\~22px
-   카드 제목: 17\~18px
-   본문: 14\~16px
-   보조 설명: 13\~14px

모바일에서도 너무 작은 글자를 사용하지 않는다.

본문 색상은 충분히 진하게 한다.

연한 회색 글자를 과도하게 사용하지 않는다.

한 줄 간격과 문단 사이 간격을 충분히 확보한다.

------------------------------------------------------------------------

## 11. 버튼 디자인 체계

버튼을 다음 3개 수준으로 정리한다.

### Primary

Orange

사용자가 현재 가장 먼저 해야 하는 행동에 사용한다.

### Secondary

Navy 또는 흰색 + Navy border

보조 행동에 사용한다.

### Completed / Status

Green

완료 또는 상태 표현에 사용한다.

모든 버튼을 Orange로 만들지 않는다.

버튼 높이, 내부 여백, 모서리 반경을 통일한다.

모바일에서는 터치 영역을 충분히 확보한다.

------------------------------------------------------------------------

## 12. 맞춤 혜택 결과 화면

정책 결과의 정보량이 많으므로 처음부터 모든 상세 내용을 펼치지 않는다.

상단에는 핵심 결과를 먼저 보여준다.

예:

> 나에게 맞는 혜택
>
> 해당 가능 4\
> 조건부 해당 가능 13\
> 직접 확인 0\
> 해당 없음 7

그 다음 우선순위가 높은 정책부터 보여준다.

정책 카드 예:

> **정책명**
>
> `[해당 가능]`
>
> 핵심 혜택 한 줄\
> 판단 이유 한 줄
>
> \[자세히 보기\] \[공식 안내\]

상세 조건은 펼쳤을 때 보여준다.

정책 카드 사이에 충분한 간격을 둔다.

기존 정책 판정 결과와 우선순위 로직은 변경하지 않는다.

------------------------------------------------------------------------

## 13. 정착 일정 화면

현재 1\~6개월 일정 구조와 데이터는 유지한다.

단순 목록보다 Timeline처럼 이해할 수 있도록 시각적으로 개선한다.

예:

`전입한 날 → 첫 주 → 정착 1~2개월 → 정착 3~5개월 → 정착 6개월 이후`

현재 사용자의 위치가 쉽게 보이도록 한다.

-   완료: Green
-   현재/다음: Orange
-   예정: Navy 또는 Gray

기존 일정 데이터와 계산 로직은 변경하지 않는다.

------------------------------------------------------------------------

## 14. Agent 실행 기록

Agent 실행 기록은 심사에서는 중요하지만 일반 사용자에게는 어렵게 느껴질
수 있다.

따라서 기본 상태는 접힌 상태로 한다.

**\[Agent 실행 기록 보기\]**

펼쳤을 때 다음 흐름을 쉽게 확인할 수 있게 한다.

1.  목표 인식
2.  도구 호출
3.  답변 검증

기술 로그처럼 지나치게 복잡하게 보이지 않도록 한다.

단, 기존 tool 이름과 검증 결과 데이터 자체는 변경하지 않는다.

------------------------------------------------------------------------

## 15. 모바일 최적화

390px 폭을 기준으로 반드시 확인한다.

모바일에서는 다음을 점검한다.

-   2열 카드 → 1열
-   버튼 터치 영역 충분히 확보
-   긴 URL 화면 밖으로 나가지 않음
-   표의 가로 스크롤 최소화
-   제목 줄바꿈 정상
-   카드 내부 글자 잘림 없음
-   버튼 겹침 없음
-   가로 스크롤 없음
-   지나치게 작은 글자 없음
-   콘텐츠 좌우 여백이 지나치게 넓지 않음

Streamlit 기본 여백 때문에 모바일 콘텐츠가 지나치게 좁아지지 않는지도
확인한다.

------------------------------------------------------------------------

## 16. 절대 변경하지 말 것

이번 작업은 **UX/UI 개선 작업**이다.

다음 데이터와 로직은 변경하지 않는다.

-   정책 24개
-   정책 판정 로직
-   정책 우선순위 로직
-   정착 일정 데이터
-   생활 정보 60곳
-   차량 권장 장소 8곳 분리 원칙
-   지역말 핵심 30개 및 확장 데이터
-   불편사항 판단 로직
-   OpenAI GPT-4.1 mini 연결
-   Agent tool calling
-   답변 검증 로직
-   공식 안내 링크 데이터
-   캘린더 저장
-   정착 리포트 저장
-   이메일 알림 신청
-   개인정보 처리 원칙
-   기존 테스트 데이터

UI 개선을 이유로 대규모 리팩터링하지 않는다.

기존 기능을 유지하면서 CSS, layout, component 배치, session_state 기반
화면 전환 등 필요한 부분만 최소 수정한다.

## 17. 작업 순서 --- 중요

**바로 전체 코드를 수정하지 않는다.**

먼저 현재 코드와 UI 구조를 확인하고 다음 내용을 보고한다.

1.  현재 UI에서 사용성이 떨어지는 부분
2.  현재 UI에서 유지해야 할 좋은 부분
3.  변경이 필요한 화면 목록
4.  각 화면의 `변경 전 → 변경 후` 구조
5.  수정이 필요한 파일
6.  기존 기능에 영향을 줄 수 있는 위험 요소
7.  가장 적은 수정으로 효과가 큰 항목의 우선순위

### 1단계

현재 UI/UX 분석과 개선안만 제시한다.

### 2단계

사용자가 개선안을 확인한 뒤 **"이 안으로 구현해줘"**라고 하면 실제
코드를 수정한다.

사용자 승인 전에는 전체 UI 코드를 한꺼번에 변경하지 않는다.

------------------------------------------------------------------------

## 18. 구현 후 테스트

UI 수정 후 기존 테스트를 모두 다시 실행한다.

다음 사용자 흐름도 추가 확인한다.

1.  첫 방문
2.  조건 입력
3.  조건 입력 완료
4.  메인 대시보드
5.  맞춤 혜택
6.  정착 일정
7.  생활 정보
8.  불편사항
9.  지역말
10. 오이소창원에게 물어보기
11. Agent 실행 기록
12. 공식 안내 링크
13. 캘린더 저장
14. 정착 리포트
15. 이메일 알림

화면 확인 기준:

-   PC: 1600px
-   모바일: 390px

다음 문제가 없어야 한다.

-   가로 스크롤
-   글자 잘림
-   버튼 겹침
-   카드 겹침
-   과도한 빈 공간
-   지나치게 작은 글자
-   클릭할 수 없는 버튼
-   기존 기능의 동작 변경

------------------------------------------------------------------------

## 19. 회귀 테스트

현재까지 반복 테스트에서 수정한 사항이 UI 변경으로 다시 발생하지 않는지
반드시 확인한다.

특히 다음을 확인한다.

-   정책 판정 결과 유지
-   학생·직장인·자영업 조건 처리 유지
-   K-패스 우선 안내 유지
-   지역말 사전 밖 표현의 안전한 처리 유지
-   생활 정보와 차량 권장 장소 분리 유지
-   진해 야경 장소 및 공식 안내 링크 정상
-   공식 안내 링크 중복 노출 없음
-   Agent 실행 기록 정상
-   답변 검증 정상
-   이메일 발송 설정 전 안내 정상
-   저장 관련 안내 순서 유지

기존에 해결한 오류를 UI 개선 과정에서 다시 만들지 않는다.

# 최종 원칙

이번 작업에서 가장 중요한 기준은 다음과 같다.

> **기능을 더 많이 보여주는 것이 아니라, 사용자가 지금 무엇을 해야
> 하는지 쉽게 이해하게 만든다.**

신규 기능을 추가하지 않는다.

검증된 데이터와 비즈니스 로직을 변경하지 않는다.

UI를 화려하게 만드는 것보다 **사용 순서, 정보 위계, 가독성, 여백, 모바일
사용성**을 우선한다.

현재까지 정상 동작하는 기능을 보호하면서 최소 수정으로 개선한다.

**첫 단계에서는 코드를 수정하지 말고 현재 UI 분석 및 개선안부터
제시한다.**
