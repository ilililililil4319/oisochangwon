## 3. 저장소 폴더 구조 --- 최신 정리안

### 3-1. `src/`란?

`src`는 **source code**의 약자다.

`app.py`가 불러 사용하는 실제 프로그램 기능 모듈을 보관한다.

현재 포함 대상 예: - `agent` - `policy_matcher` - `policy_engine` -
`settlement_engine` - `mission_manager` - `progress_manager` -
`state_manager` - `activity_manager` - `naver_map_links` -
`policy_resource_manager`

따라서 `src/`는 그대로 유지한다.

### 3-2. `app.py`와 `requirements.txt`

둘 다 저장소 최상위(root)에 둔다.

``` text
oiso_changwon/
├─ app.py
├─ requirements.txt
```

-   `app.py`: Streamlit Cloud 배포 시작 파일 --- **위치 변경 금지**
-   `requirements.txt`: 배포 시 필요한 Python 패키지 목록 --- root 유지

## 5. 모바일 미리 보기 앱 문제 --- 반드시 인계

### 확인된 실제 현상

**모바일 미리 보기 앱에서 캐시를 삭제했는데도 최신 배포 화면으로
업데이트되지 않았다.**

따라서 다음처럼 기록하면 안 된다.

``` text
캐시 삭제 후 해결됨
```

해결되지 않았으므로 사실과 다르다.

### 모바일 최종 검증 방법

모바일 미리 보기 앱은 최종 판정 기준으로 사용하지 않는다.

다음 순서로 확인한다.

1.  PC 브라우저에서 최신 Streamlit 배포 확인
2.  실제 휴대폰 Chrome/Safari에서 배포 URL 직접 접속
3.  기존 탭을 재사용하지 말고 새 탭에서도 확인
4.  시크릿/개인정보 보호 모드 확인
5.  가능하면 다른 브라우저 또는 다른 휴대폰에서 교차 확인
6.  PC와 실제 모바일 브라우저에서 최신 변경점이 같은지 비교
7.  최종 제출용 모바일 캡처는 실제 모바일 브라우저 화면으로 새로 저장

미리 보기 앱과 실제 모바일 브라우저 결과가 다르면 **미리 보기 앱의 캐시
문제와 실제 Streamlit 배포 문제를 구분**해서 기록한다.

## 13. 절대 하지 않을 것

-   여러 대화창에서 같은 저장소를 동시에 수정하지 않음
-   파일 구조 정리와 큰 기능 변경을 한 번에 섞지 않음
-   `app.py`를 `src/`로 이동하지 않음
-   `requirements.txt`를 하위 폴더로 이동하지 않음
-   팀 공유 자료를 최종 제출용 `docs/`에 섞지 않음
-   자체 테스트 문서와 사진을 서로 다른 상위 폴더에 다시 분산하지 않음
-   정책 판정 로직을 이유 없이 교체하지 않음
-   정책·지역말 데이터를 출처 확인 없이 추가하지 않음
-   미등록 지역말을 AI가 임의 추정하지 않음
-   검증되지 않은 전화번호/링크를 생성하지 않음
-   모바일 미리 보기 앱이 캐시 삭제로 해결됐다고 기록하지 않음
-   실제 모바일 브라우저를 확인하지 않고 `모바일 정상`이라고 기록하지
    않음
-   테스트를 실행하지 않고 기존 `101개 통과`를 현재 결과로 기록하지 않음
-   실제 API Key를 채팅·GitHub·문서·영상에 남기지 않음
-   GitHub push는 이혜경의 명시적 지시 없이 진행하지 않음
