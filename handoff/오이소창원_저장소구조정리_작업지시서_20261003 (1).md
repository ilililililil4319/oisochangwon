## 1. `src/`의 의미

`src`는 **source code(소스 코드)**의 약자다.

오이소창원에서 `src/`에는 앱 화면을 직접 실행하는 시작 파일이 아니라,
`app.py`가 불러서 사용하는 실제 기능 모듈을 둔다.

예: - `agent.py` - `policy_matcher.py` - `policy_engine.py` -
`settlement_engine.py` - `mission_manager.py` - `progress_manager.py` -
`state_manager.py` - `activity_manager.py` - `naver_map_links.py` -
`policy_resource_manager.py`

따라서 `src/`는 그대로 유지한다.

`app.py`는 Streamlit Community Cloud의 **배포 시작 파일**이므로 저장소
최상위(root)에 그대로 둔다.

`requirements.txt`도 배포 환경에서 패키지를 자동 설치할 때 쉽게 찾을 수
있도록 **저장소 최상위(root)**에 둔다.

즉 다음 두 파일은 이동하지 않는다.

``` text
oiso_changwon/
├─ app.py
├─ requirements.txt
```

### 구조 정리 원칙

1.  기존 `docs/자체테스트/`의 **Test Case 문서와 자체 테스트 기록**은
    `tests/self_test/docs/`로 이동한다.
2.  기존 `screenshots/self_test_20261002/`의 **셀프 테스트 사진 26장**은
    `tests/self_test/screenshots/`로 이동한다.
3.  자체 테스트의 문서와 증빙 사진을 `tests/` 아래에서 함께 관리한다.
4.  일반 작업 과정 캡처는 자체 테스트와 섞지 않고 `docs/work_process/`에
    둔다.
5.  팀 공유 자료는 `docs/team_share/`로 둔다.
6.  최종 결과물은 `deliverables/`로 분리한다.
7.  발표 PPT와 영상은 `deliverables/presentation/` 아래에서 각각
    관리한다.
8.  큰 영상 파일을 GitHub에 직접 올릴지 여부는 파일 용량을 확인한 뒤
    결정한다. GitHub에 넣지 않는 경우 `video/README.md`에 최종
    파일명·보관 위치·제출 링크를 기록한다.
9.  `handoff/`는 내부 작업용이며 제출 직전 PC에 별도 보관한 뒤 GitHub
    제출본에서는 삭제한다.

## 4. README.md 수정

### 개발 작업 과정 수정

README의 `개발 작업 과정`에서 **2026-10-02(금) 내용이 4줄로 나뉘어

내용을 삭제하는 것이 아니라 10/2에 수행한 핵심 작업을 한 줄 안에
요약한다.

