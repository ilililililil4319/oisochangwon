## 2. 프로젝트 개요

**문제.** 창원은 청년 순유출이 이어지는 도시이고, 전입 청년이 받을 수 있는 혜택은 여러 기관·사이트에 흩어져 있습니다. 기업노동자 전입지원금처럼 ‘전입 후 6개월’ 같은 시점 조건이 있어 신청 시기를 놓치기 쉽고, 차가 없으면 갈 곳·할 일도 모르며, 불편을 어디에 말해야 할지와 낯선 지역말도 정착을 어렵게 합니다(근거는 기획안 Ⅰ장).

**사용자.** 창원에 막 전입한 19~39세 청년(직장인·자영업·학생·기타). 대표 페르소나 ‘코디2026’: 만 28세, 2026-09-20 용인시에서 전입, 창원 기업 재직, 1인가구, 차량 없음.

**목표(8일).** 실명·연락처 없이 나의 조건만으로 ① 받을 수 있는 혜택을 판정·설명하고 ② 1~6개월 정착 일정을 만들어 저장·내보내며 ③ 불편 접수 창구와 ④ 지역말 뜻을 검증된 자료로 안내하는 MVP.

**차별성.** 창원청년정보플랫폼이 정책 게시·신청 중심이라면, 오이소창원은 AI가 내 조건으로 정책 24건을 **실제 판정해 4단계(해당 가능·조건부 해당 가능·직접 확인·해당 없음)로 분류**하고, 신청 가능한 이유/안 되는 이유·지금 할 일·신청 가능 예정일을 설명합니다. 그 결과를 **📅 내 캘린더**(하루 전 알림)와 **📄 정착 리포트**(할 일·혜택 신청 가능일을 시간 순서로, 공식 링크 포함)로 저장하고, **✉️ 이메일 알림**은 원할 때만 동의 후 보냅니다. 신청은 플랫폼·공식 사이트로 연결해 보완 관계입니다.

| ④ 창원 지역말 번역 | 핵심 30개 → 공식 출처 확장 사전 2,223개 순서로 조회 | 문헌 기준 뜻·쓰임·출처, 사전 밖은 “별도 확인 필요” + 우리말샘 링크 |
| 오이소창원에게 물어보기 | 한 문장 질문 → 안전 확인 → 도구 선택·호출 → 답변 검증 | 답 + 공식 링크 + Agent 실행 기록 |

### 3-2. Agent Architecture 및 Workflow

```
나의 조건 입력(세션 상태·SQLite) ─┐
한 문장 질문 ─→ ① 안전 확인(긴급·위기 문장은 AI 없이 즉시 안내)
             → ② 목표 인식: GPT-4.1 mini가 필요한 도구 선택(계획)
             → ③ 도구 호출: get_my_situation · search_policies · search_activities · lookup_dialect · find_complaint_channel
             → ④ 답변 검증: 답 속 전화번호·링크가 도구 결과(검증 DB)에 있는지 대조 → 없으면 1회 재작성 → 그래도 없으면 규칙 기반 안내
             → ⑤ 결과: 답 + 공식 링크 + Agent 실행 기록
End-to-End: 조건 입력 → 정책 판정(4단계) → 정착 일정 생성 → 할 일 체크 저장 → 캘린더·리포트 저장 / 이메일 알림(동의 시)
```

| Agent 6요소 | 구현 |
| --- | --- |
| Goal | 질문의 목표 인식(실행 기록 ‘목표 인식’), 조건 입력으로 사용자 목표 설정 |
| Planning | 도구 선택 순서 결정, 전입일 기준 180일 일정 계획 |
| Reasoning | 정책 4단계 판정(하는 일·거주기간·연령 규칙), 불편 6단계 분류, 차량 유무별 이동 방식 |
| Tool Use | 검증 DB 도구 5개, 날짜 계산, 캘린더 파일 생성, SQLite 저장, 이메일 발송(SMTP) |
| Memory/State | 조건·할 일 체크·기록을 닉네임 기준 저장하고 다음 접속 때 복원 |
| Feedback/Evaluation | 답변 검증 후 재작성·규칙 대체, 사전 밖 단어는 짐작하지 않음 |
